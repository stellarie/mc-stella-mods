## Objective

## Plan

### Scope and sequence

Keep these behavior changes out of the Stage 2 progression and catalogue-cleanup PR. Plan them as separate follow-up features after Stage 2 merges. Undertow changes an existing trident effect. The melee enchant adds a separate status-effect behavior.

The current Undertow definition supports tridents and has `max_level: 3` (`src/main/resources/data/mod-stella-equips-enchants/enchantment/weapon/undertow.json:3-10`). It uses `minecraft:post_attack` to apply an impulse to the attacker (`undertow.json:12-24`). The existing test at `src/gametest/java/com/stella/equips/EffectEnchantGameTest.java:917-941` holds the trident and calls `thrower.attack(victim)`. It checks velocity, not a thrown projectile or the required endpoint.

`StellaEquips.onInitialize` registers custom handlers for Deflection, Ore Regeneration, Ore Mender, player power, and readouts (`src/main/java/com/stella/equips/StellaEquips.java:22-39`). `weapon/chill.json:12-44` demonstrates the existing `minecraft:post_attack` pattern for applying Slowness to a victim. The new enchant must also grant Speed to a player attacker.

### Design preview

```text
Undertow hit: [thrower] ---> [midpoint] <--- [target]
                                      <--- 1 block --->
Melee hit:    [player + enchant] ---> [target]
              Speed to player; Slowness to target
```

### Movement contract

`EnchantmentEntityEffect.apply` receives the living item owner and the affected target after accepted damage. The direct path uses `Player.attack`; the thrown path uses `ThrownTrident.onHitEntity`. In 26.3, the thrown path dispatches post-attack effects before projectile knockback. The `ServerLevelMixin` invokes `END_LEVEL_TICK` at the end of the level tick.

Capture both pre-hit `Entity.position()` anchors in `apply`. Queue both entity UUIDs, the source level, and both anchors. At `END_LEVEL_TICK`, resolve only already-loaded entities in the same level. Require both entities to remain alive and present. Do not load chunks. Read their current positions before validating the move.

Let `A` be the owner position, `V` the victim position, `D = V - A`, `L = length(D)`, and `M = (A + V) / 2`. If `L` is non-finite or `L <= 1.0`, do nothing. Otherwise let `U = D / L`, then set `A_end = M - 0.5 * U` and `V_end = M + 0.5 * U`. Use all three coordinates. This preserves the pre-hit midpoint and gives a 1.0-block anchor gap.

Before moving either entity, validate both swept paths against blocks and the world border. Check unrelated-entity collisions at both destinations. Exclude the paired entity from occupancy checks, then assert that the final hitboxes do not overlap.

If any check fails, move neither entity from its current position. Validate the swept paths from the current positions to the computed endpoints. Apply both endpoints in one server-side operation. If either teleport fails, restore both positions from immediately before that operation. On success, clear both delta movements and reset both fall distances. Gravity resumes on the next level tick.

Allow any living owner, including mobs. Skip an ownerless projectile because no thrower exists. At `END_LEVEL_TICK`, skip the pair if either actor is a passenger or has passengers.
